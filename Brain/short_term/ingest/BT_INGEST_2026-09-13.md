## 2.5 · ⭐ THE METHOD FINDING — a 200 with the wrong bytes is a FAILED fetch

**The first fetch of this collection downloaded Google's "virus scan warning" HTML page as `Module - Building Technology.pdf` — and the harness counted it OK**, because the interstitial is *text* and the harness's check accepted text. **116 MB of course module was silently absent from a run that reported "48 fetched, 0 failures."**

Nothing about that output looked wrong. It is the **PEC-table failure in a different costume**: an artifact that is the right shape and the wrong contents, passing a check that only asked for plausible.

**THE RULE THIS ESTABLISHES:**
> **A fetch is successful only if the received bytes match the *declared type*.** HTTP 200, a non-zero size, and a plausible file are **not** evidence. Validate the magic bytes against the extension; on mismatch, retry the large-file confirm flow and, if it still fails, **fail loudly**.
> A document fetch that silently yields a web page is a *missing document*, not a downloaded one.

**Fixed in `scripts/ingest_collection.py` (this patch), with three additions:**
1. **the declared-type gate** — `DECLARED = {.pdf: pdf, .xlsx/.pptx/.docx: zip, .ppt/.xls/.doc: ole …}`; a type mismatch is a **FAIL**, never a pass, and it is logged;
2. **the >100 MB confirm-token flow** — parse the interstitial's `id/export/confirm/uuid` form and re-request from `drive.usercontent.google.com`; verified working (116.08 MB, `%PDF-1.6`);
3. **cache validity** — a cached copy is re-fetched unless its bytes match the declared type (the first run's 2,449-byte "PDF" sat in the cache and would have been counted as present).

*Caught by re-reading the bytes instead of the log. The log said OK. The file was a web page.*

## 7 · RUNBOOK — the repeatable procedure (now with the restraint doctrine in code)
```text
ingest_collection.py list    --url "<folder-url>"  --out <manifest.json>
ingest_collection.py fetch   --manifest <manifest.json>  --dest <SCRATCH>  --repo .  --max-size <MB>
ingest_collection.py extract --dir <SCRATCH>  --out <report.json>
ingest_collection.py verify  --pdf <SCRATCH>/<file>.pdf  --page <N>  --repo .
```
**`<SCRATCH>` is a working directory OUTSIDE the repository** — the harness refuses a destination inside the repo, because binaries never touch it (II.6 r.8).
**`--max-size` implements the Restraint Doctrine:** files above the cap are **SIZE-SKIPPED and logged** — *a skipped file is lawful; an unlogged one is not.* The log is built by scanning the destination, so a file cached on an earlier run still appears in the record.
Then: write the DIGEST → create registry rows → **delete the binaries** → append the ACCESS LOG.
**⚠️ For this collection the runbook must end with a second pass**, because the readable half is not the valuable half — see §2.
