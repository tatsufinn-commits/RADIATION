# 🔗 EXTERNAL SOURCES INDEX (`Brain/external_sources/INDEX.md`)
## The Approved External Collection Catalog — Commander-Gated
**Version:** 1.0 | Constitutional basis: II.6 (external-sources clause), IV.4 (Canon Gate for entries)
**Origin:** Commander's proposal (proven pattern from TAMAKEE operations)

## WHAT THIS REGION IS
A catalog of Commander-approved external collections (Google Drive folders and
kin) holding bulk material too large for the repository: PDFs, slide decks,
document archives, datasets. The repo stays light; the reachable knowledge
grows. **This region holds POINTERS and their verified digests — the catalog
is never itself citable evidence.**

## THE RULES
1. **Commander-gated entry:** collections enter this index ONLY by
   Commander-approved Patch. No AI adds a link on its own judgment.
2. **Capability declaration:** every session states in its Scan Declaration:
   `EXTERNAL ACCESS: Drive-capable | not capable`.
3. **Drive-capable sessions:** open links directly; contents are ordinary
   sources — curator ingests, claims are graded (I.2) and triangulated (I.3)
   like any other material. No special ceremony, no promotion bypass.
4. **Drive-blind sessions:** work from each collection's MANIFEST/DIGEST only,
   and MUST NEVER represent catalog knowledge as having read the underlying
   documents (access-honesty — an I.1 matter).
5. **Access logging:** every access attempt appends ACCESSIBLE / DEAD /
   AUTH-BLOCKED + date to the collection's ACCESS LOG.
6. **Decay:** a collection whose last-verified date exceeds 90 days is flagged
   for re-verification (I.4 volatile class — links and permissions drift).
7. **Staging, not substitute:** truly important documents should be properly
   ingested through the pipeline into the Brain; this catalog feeds the Brain,
   it does not replace it.
8. **Manifest-first:** never enumerate or bulk-open a live collection. Pick
   files *by name* from the MANIFEST in each collection file; fetch only those.
   Browsing costs zero because the manifest already exists.
9. **Necessity test:** before every fetch, state which file serves which
   claim/task. No stated need → no fetch.
10. **Fetch budget (HARD):** max **3 files per collection, 6 files total per
    session**. Need more? Say so and stop — only the Commander extends a run.
11. **One-at-a-time:** open → extract → write to DIGEST → release. Never hold
    multiple large files at once.
12. **No mirroring:** never download/copy a collection wholesale into the
    workspace. Only extracts (quotes, page-cites, summaries) enter the Brain.
13. **Large-file protocol:** oversized/unreadable-in-one-pass files get
    partial/paged reads; if unsafe, log `SIZE-SKIPPED` in the ACCESS LOG and
    move on. A skipped file is lawful; a crashed session is not.
14. **DIGEST-before-refetch:** check the DIGEST first — refetching already-
    extracted material is forbidden waste. Every restrained session enriches
    the DIGEST, so future sessions fetch less. The system gets cheaper as it
    ages.
