# 🏗️ SCAFFOLDING — The Temporary Support Layer
**Version:** 1.0.0 | Constitutional basis: III.6, IV.4 | Ratified by THE COMMANDER

## 1. WHAT SCAFFOLDING IS
A scaffold is a TEMPORARY WORK STRUCTURE the AI erects around a task: step
sequences, worksheets, checklists, and fill-in frames that force rigor WHILE
WORKING. Scaffolds are construction equipment, not the building: **/styles/
shapes the DELIVERABLE; scaffolding shapes the WORK.** A finished deliverable
never contains scaffold matter (see §3 FADEABILITY).

## 2. WHEN TO USE EXISTING vs GENERATE NEW
- **USE core/** if a scaffold exists for your skill/task type. Core use is
  MANDATORY for: research sorties, triangulation, inspections, Nota
  distillation, curator ingestion runs, repo decodes, Patch notes, and Scan
  Declarations.
- **GENERATE into generated/** ONLY when (a) no core scaffold fits the task
  shape, AND (b) the task is complex enough to need staged support (3+ steps
  or 5+ sources). Name it `YYYY-MM-DD_task-slug_scaffold-name.md`, declare it
  in the Scan Declaration. Single-step tasks need no scaffold — do not
  scaffold the trivial. (@Data never requires scaffolds except the stripped
  triangulation gauntlet.)
- **NEVER modify core/ directly.** Refinements go to improved/ with a rev-note.

## 3. STANDARDS FOR GOOD SCAFFOLDING
- **CLARITY** — any AI, any size, executes it without interpretation. Numbered
  steps, one action per step, no prose walls.
- **MODULARITY** — one scaffold = one job. Scaffolds compose (a research sortie
  invokes the triangulation gauntlet); they never duplicate each other's steps.
- **AUDITABILITY** — every checkbox/field demands EVIDENCE (a path, a source
  ID, a quote), never a bare "done". An inspector must be able to verify
  compliance from the artifact alone.
- **FADEABILITY** — the scaffold detaches cleanly: deliverables carry no
  scaffold residue. Completed scaffold artifacts are filed to
  Brain/short_term/ as session working papers, then triaged at session close.

## 4. PROMOTION RULES INTO core/
1. Candidate has ≥3 logged successful uses (cerebellum/routines/ entries
   reference it by name).
2. Author-AI files it to improved/ with: purpose, usage evidence, and which
   §3 standard(s) it demonstrably serves.
3. surgeon audits it against §3. Fail = returned with defects listed.
4. **THE COMMANDER RATIFIES** (IV.4 Canon Gate), via 🟠 Patch. Only
   ratification moves a file into core/. No exceptions, no self-promotion.

## 5. NAMING CONVENTION
`proc_*` = process scaffolds (staged work support) · `form_*` = output-form
templates (fixed formats for recurring artifacts). Both live in core/ —
one support layer, per the Commander's templates-merge ruling.
