# 🎨 STYLE HEURISTICS (`cue/style-heuristics.md`)
## Style-Selection Guidance for Phase 3 (ASSESS)
**Status:** heuristics — the AI chooses by judgment of what FORM serves the outcome; AUTO selections are declared + justified (III.4)

| Prompt shape / task nature | Likely style |
|---|---|
| General research corpus | `research.md` (@Gather default) |
| "compare X and Y / which is better" | `comparative-analysis.md` |
| "state of the art / what does the literature say" | `literature-review.md` |
| "for my thesis / defense / dissertation" | `thesis.md` |
| "audit / check for problems / verify integrity" | `audit.md` |
| Repo comprehension | `msr.md` (@Decode default) |
| "experiment / test whether / methodology" | `scientific-research.md` |
| Synthesis of existing studies only (no primary work) | `secondary-research.md` |
| Subject intelligence file | `dossier.md` |
| @Data answers | `quickfire.md` (implicit) |

## RULES OF THUMB
1. The style serves the DELIVERABLE element of the tuple, refined by DEPTH.
2. When two styles fit: choose the one whose [MANDATORY] sections the task can
   genuinely fill; declare the runner-up.
3. A style never overrides a mode's charter (III.2) — e.g. no style can add a
   conclusions section to @Gather output (no-Nota rule).
